CLEAR BY DESIGN

Privacy, in plain words.

QuickPost for Tumblr · Last updated October 20, 2026

Pre-release policy — review required before public distribution.

This page describes the current source implementation and local tests. Live Tumblr consent, the production Cloudflare configuration, and provider retention practices have not been verified for this application. These are marked below. This is not a claim that the extension is already publicly available or that the OAuth backend is deployed.

1. Who is responsible

QuickPost for Tumblr is an independent Chrome extension maintained by the owner of the QuickPost website repository. It is not affiliated with Tumblr. Contact the maintainer through the support tracker. Do not post tokens, passwords, private posts or personal account details in a public issue.

Review before public distribution: confirm the maintainer’s legal identity and an appropriate private channel for privacy or security requests. The current contact is a public GitHub issue tracker.

2. What you choose to share

The extension handles the images, links, selected text, captions, tags and destination blog that you choose. Context menus capture content only when you use them; the implementation does not include background page-reading content scripts. You review a selection in the editor before creating a post.

When you import an image from a website, Chrome asks for access to that image’s origin. The extension downloads it directly from that origin, without cookies or a referrer. The source server receives the request and your IP address. Previously approved optional host permissions may remain granted until you remove them in Chrome.

3. Connecting your Tumblr account

Authentication uses Tumblr OAuth 2.0. You enter your Tumblr password on Tumblr, not in QuickPost. The requested scopes are basic, write and offline_access, for account/blog access, posting and token renewal.

The extension sends the authorization code and the information needed to validate the OAuth flow to a dedicated OAuth service. A Cloudflare Worker is prepared to exchange and renew tokens using the application’s confidential Tumblr client secret. That secret is not included in the extension.

Pending live verification: successful registration of the redirect URL, actual consent, returned scopes, token rotation, and deployed Workers Secrets configuration. The Worker is currently prepared for local use and has not been deployed.

4. What stays on your device

  • Chrome local storage: selected blog, tags, posting mode and an installation-specific private signing key. These remain until the extension’s local data is removed or the extension is uninstalled.
  • Chrome session storage: access token, an encrypted refresh-token envelope, temporary OAuth state and pending context-menu selections. Session storage is cleared when the browser session ends or the extension is reloaded or disabled. Pending selections have a ten-minute logical expiry and are removed when consumed or pruned.
  • Editor memory: selected image files, caption and link while the editor remains open. Closing the tab discards this unsent content.

Tokens are not stored in Chrome sync storage. The access token is briefly available to the trusted editor so it can call Tumblr directly. The refresh token is encrypted by the OAuth service; its unencrypted value is handled there during token operations. A session has a maximum duration of eight hours.

Chrome storage is not a separate encrypted vault. Someone with control of your device or browser profile may be able to access local data. The installation key is not the Tumblr client secret.

5. Where posts and images go

Blog queries, uploads and post creation go directly from the extension to Tumblr’s official API. Image bytes do not pass through the OAuth Worker. Queued posts use Tumblr’s native queue; saved drafts are stored on Tumblr, not in a separate QuickPost database. Tumblr’s policies and account settings govern content after it reaches Tumblr.

The prepared OAuth backend does not use a database, Workers KV, Durable Objects or image storage. It processes authorization codes and tokens in order to carry out OAuth operations. Rate-limiting bindings keep service-managed counters.

6. Service providers and operational data

Tumblr processes OAuth requests and the posts and media you submit. Cloudflare will process OAuth service requests when the Worker is deployed, including network metadata such as IP addresses; the Worker uses an IP signal and installation identifier to limit abuse. GitHub Pages hosts this informational website and may process visitor IP addresses and other request metadata.

The current application code does not send analytics or advertising events. This website contains no analytics scripts, tracking pixels, remote fonts or embedded third-party media, and does not set application cookies. Opening GitHub contact links or Tumblr authentication takes you to those services.

The Worker’s application code does not log token values, authorization codes or request bodies, and its checked-in configuration disables Workers observability. This does not establish what operational metadata providers independently retain.

Review before production use: provider terms, applicable retention periods, production logging and the final account settings. No unverified guarantee of zero provider logging or worldwide legal compliance is made.

Provider notices: Tumblr privacy policy, Cloudflare privacy policy, GitHub privacy statement.

7. Disconnecting and removing data

Disconnecting clears the extension’s local session credentials. It does not automatically revoke access tokens that Tumblr has already issued. To revoke the application’s access, remove its authorization in Tumblr’s connected-app settings.

Uninstall the extension to remove its Chrome storage, or clear its stored data through Chrome’s extension developer tools. Optional site permissions can be removed through Chrome’s extension settings. Posts and drafts already sent to Tumblr must be managed or deleted on Tumblr.

For questions about data held by the maintainer, use the contact tracker without including sensitive details, and request a private follow-up channel when needed.

8. Updates

This policy will be reviewed before public distribution and when the application’s data handling changes. Material changes will be reflected on this page with an updated date. The pre-release review notices must be resolved rather than silently treated as verified claims.
